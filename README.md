# Claude Queue

> 🤖 **本專案完全由 Anthropic 的 Claude Opus 5.5 開發。** 作者提供需求規格，所有程式碼、介面文字、文件與測試都由 Claude Opus 5.5 在 Claude Code 中撰寫完成。詳見[關於這個專案的開發方式](#關於這個專案的開發方式)。
>
> 💬 **討論群組（Discord）：<https://discord.gg/yEpS7vSJtv>** 有問題、建議或想分享用法都歡迎來聊。

claude.ai 用量達上限（5 小時 session 上限或每週上限）時，把你按下送出的訊息先存起來，等額度重置後通知你，並協助把訊息填回原對話、由你確認後送出。

> ⚠️ 這是**非官方**的社群專案，與 Anthropic 沒有隸屬或合作關係，也未經 Anthropic 認可。「Claude」是 Anthropic 的商標，這裡只用來說明本工具適用的網站。

### 為什麼需要它？

用量滿的時候，常常是你正想到一個好問題、或剛打完一大段 prompt。這時通常只能：把文字複製到別處、記住要在幾點回來、到時候再找回原本的對話貼上。Claude Queue 把這些步驟自動化：

```
你按下送出 ──► 偵測到用量已滿 ──► 存入佇列（含對話網址）──► 清空輸入框
                                                │
           重置時間到 ◄─────────────────────────┘
               │
               ▼
   確認真的已重置 ──► 桌面通知 ──► 你點通知 ──► 開啟原對話、自動填入文字
                                                       │
                                                       ▼
                                          你按「送出」（或開啟自動送出）
```

### 特色

- **零干擾**：用量沒滿時完全不攔截，跟沒裝一樣
- **不會弄丟訊息**：確認存檔成功才清空輸入框；任何一步失敗都會保留在佇列，並提供「複製文字」
- **附件也能排隊**：圖片、PDF 等你從電腦加入的檔案會連同文字一起存起來，重置後用頁面上的上傳按鈕加回去、等上傳完成才送出
- **由你決定何時送出**：預設是通知＋確認列，自動送出要你自己去設定頁開啟
- **自動重設（選用）**：5 小時工作階段歸零時自動送出一則短訊息，讓下一個工作階段馬上開始倒數，起床時可以連續用到兩個工作階段
- **防重複送出**：多個分頁、手動送出、送出中關閉分頁等情況都有處理
- **準確的重置時間**：優先讀 claude.ai 的用量資訊，讀不到才解析頁面提示文字，推估的時間會標示「估計」
- **改版時好修**：DOM 選擇器與用量解析各自集中在一個檔案，找不到元素會明確提示
- **繁體中文介面**，已預留 i18n 結構

### 基本原則

- Manifest V3、純 JavaScript，**不需要建置**
- 只在 `https://claude.ai/*` 運作；權限只有 `storage`、`alarms`、`notifications`
- 沒有外部伺服器、不上傳任何資料、不載入遠端程式碼
- 不重放或偽造 claude.ai 的內部請求：送出一律透過頁面上的輸入框與送出按鈕，跟你自己操作一樣
- 不會繞過任何用量限制，只是幫你**延後**送出

## 安裝（載入未封裝項目）

> 📖 第一次安裝？看 **[新手教學：從安裝到使用](GUIDE.md)**，有更詳細的步驟、睡前自動重設檢查清單與疑難排解。

1. 開啟 `chrome://extensions`
2. 打開右上角「開發人員模式」
3. 按「載入未封裝項目」，選擇這個資料夾（裡面有 `manifest.json` 的那層）
4. 把 Claude Queue 釘選到工具列（拼圖圖示 → 圖釘）
5. **已經開著的 claude.ai 分頁要重新整理一次**，content script 才會載入

更新程式碼後：在 `chrome://extensions` 按 Claude Queue 的重新整理鈕，再重新整理 claude.ai 分頁。

## 使用方式

### 平常
什麼都不用做。用量未滿時，擴充功能不會攔截任何東西。

### 用量滿了
1. 照常輸入訊息，按 Enter 或送出按鈕
2. 擴充功能會攔下這次送出、再查一次用量確認真的滿了，然後把文字、附件、對話網址、時間存入佇列
3. **確認存檔成功後**才清空輸入框（附件也會從輸入區移除），頁面下方會顯示：「用量已滿，訊息已排入佇列，預計 HH:MM 重置」
   - 如果重置時間是從頁面提示文字推估、或完全解析不到（預設 5 小時後），會加註「（時間為估計）」
4. 工具列圖示會顯示佇列數量（橘色＝等待中、綠色＝可送出、紅色＝有失敗項目）

### 額度重置後
1. 到了重置時間（＋30 秒緩衝），擴充功能會確認用量真的已重置；還沒重置就每 2 分鐘重試，最多 10 次
2. 發出桌面通知「Claude 額度已重置」
3. 點通知 → 開啟（或切換到）原對話分頁 → 文字自動填入輸入框
4. 頁面下方出現確認列：**已還原訊息，要送出嗎？**
   - **送出**：按下頁面上的送出按鈕，確認訊息出現在對話中後才從佇列移除
   - **取消**：從佇列移除這則訊息，文字留在輸入框讓你自行處理
   - **保留在佇列**：清空輸入框，訊息留在佇列，之後可從 popup 再試
5. 同一對話若有多則排隊訊息，會等 Claude 回應完成後依序還原下一則

### 自動重設（選用，預設關閉）
claude.ai 的 5 小時工作階段要等你**送出第一則訊息**才開始倒數。晚上睡覺時，工作階段結束後就一直停在歸零，起床送出第一則訊息後才重新開始。

開啟「自動重設」後：
1. 工作階段結束（＋90 秒緩衝）時，擴充功能確認目前沒有進行中的工作階段，而且每週上限沒滿
2. 開啟一個**專用對話**（第一次會開新對話，之後都用同一個；被刪除時會自動再開一個），填入訊息（預設 `Hello World!`，可在設定頁修改），倒數 3 秒後送出
3. 下一個 5 小時工作階段就從這時開始倒數。例如凌晨 3 點自動送出，早上 7 點起床時，目前的工作階段 8 點就會重置，可以先用 1 小時，再接著用一個完整的新工作階段

注意：
- Chrome 必須開著、**電腦不能睡眠**（macOS 可以在終端機執行 `caffeinate -i`，或調整「電池／能源」設定），claude.ai 要保持登入
- 送出時會把 Chrome 視窗帶到最前面（全天都會運作，包含白天）
- 如果佇列裡有訊息正在自動送出，就不另外送（那則訊息本身就會開始新的工作階段）；你自己已經用手機等裝置送過訊息時也不會送
- 連續失敗 3 次會暫停，並發桌面通知；你再次使用 Claude 或重新開啟設定後恢復

### Popup（點工具列圖示）
- Session（5 小時）與每週用量百分比、重置時間與倒數、資料來源
- 佇列清單：每則可 **編輯** 文字、**立即嘗試**（開啟原對話並還原）、**刪除**（兩段式確認）

### 設定頁（popup 右上角 ⚙，或在擴充功能頁按「詳細資料 → 擴充功能選項」）
- **重置後自動送出（不需確認）**：預設關閉。開啟後會在重置時自動開啟分頁、填入，3 秒倒數後送出（倒數期間可取消）。開啟前會跳出確認對話框
- **自動重設**：工作階段歸零時自動送出一則訊息（見上方說明），以及要送出的文字
- 桌面通知開關
- 用量輪詢頻率（預設 2 分鐘；多個分頁共用結果）
- debug log 開關、檢視／複製／清除 log
- 模擬「用量已滿」（測試用，見 [TESTING.md](TESTING.md)）
- 清除所有資料

## 運作方式

### 用量偵測（`src/content/usage.js`）
content script 在 claude.ai 頁面內以你的登入狀態做 GET 請求（與頁面同源，不需要額外權限）：

| 端點 | 用途 |
|---|---|
| `GET /api/organizations` | 取得組織 uuid（優先讀 cookie `lastActiveOrg`） |
| `GET /api/organizations/{uuid}/usage` | `five_hour` / `seven_day` 的 `utilization`（0–100）與 `resets_at` |

這兩個都是非公開的內部端點。2026-11 查證時，`/api/organizations` 確實存在（未登入會回 `account_session_invalid`）。回應格式是根據社群工具的紀錄，與 Claude Code 的 `/api/oauth/usage` 格式相同：`five_hour`/`seven_day` 物件，各有 `utilization` 與 `resets_at`。解析器也接受欄位別名與 epoch 時間戳。**第一次使用請照 TESTING.md 的第 0 步，用 DevTools 確認你帳號的實際回應。**

- 輪詢：開著 claude.ai 時每 N 分鐘一次；前景分頁優先，結果存在 `chrome.storage.local` 給所有分頁共用
- 送出前再查：你聚焦輸入框時會刷新一次；攔下送出後會再查一次（最多等 3 秒），如果其實已恢復，就不排隊並提示你再按一次
- 備援：端點失敗時，掃描頁面上**特定區域**（`role=alert/status`、輸入框附近的提示列，且文字少於 400 字）是否出現「usage limit」「已達上限」等字樣，並解析重置時間；解析失敗就以 5 小時後作為保守預設，標示「時間為估計」
- 模型別的週上限（如 `seven_day_opus`）只顯示，不列入「已滿」判斷，因為擴充功能無法得知你目前使用哪個模型；如果真的被擋，頁面上的提示會讓 DOM 備援偵測接手

### 攔截（`src/content/interceptor.js`）
- 在 `window` 的 capture 階段監聽 `keydown`（Enter，不含 Shift+Enter，**也不含輸入法選字中的 Enter**）、`click`（送出按鈕），以及 disabled 送出按鈕上的 `pointerdown`
- 只處理 `isTrusted` 的真實使用者事件；擴充功能自己觸發的送出不會被攔
- 有附件時（`src/content/attachments.js`）：
  - 你親手加入檔案的當下（選檔、拖放、貼上圖片，只看 `isTrusted` 事件）就記下 `File`；排隊時把輸入區的每張附件卡片和記下的檔案一一對應（看得到檔名就比檔名，否則數量要相同）
  - 對不上的附件（Google Drive／GitHub、長文字貼上轉成的附件、擴充功能載入前就加的）→ 顯示「這則訊息有無法保存的附件…」，**不攔截**，照原本行為處理
  - 單檔超過 30MB、超過 20 個附件，或佇列裡的附件總共超過 300MB → 不排隊
  - 只有附件、沒有文字的訊息不排隊（重複送出偵測靠文字比對）
  - 檔案先逐一交給 service worker，存在擴充功能自己的 IndexedDB（`src/background/filestore.js`），項目建立成功才清空輸入區
- 還原有附件的項目時：用頁面上的 `<input type="file">` 把檔案加回去（備援：合成拖放），等附件卡片到齊、上傳指示消失才填文字與倒數；按送出前會再確認一次
  - 輸入區原本就有附件 → 自動模式不送並通知；手動模式讓你選「移除後重新檢查／一起送出／保留在佇列」
  - 檔案加不回去或上傳逾時 → 自動模式重新整理後重試（最多 2 次），仍失敗就通知；手動模式可以「下載附件」自己加入

### 填入輸入框（`src/content/editor.js`）
claude.ai 的輸入框是 ProseMirror 富文字編輯器，直接改 DOM 會被編輯器的內部狀態覆蓋，React 端也不會知道「有內容可送出」。依序嘗試以下方法，每一步都會讀回比對，成功就停：

1. **`document.execCommand('insertText')`（主要方法）**：瀏覽器會產生真實的 `beforeinput`/`input` 事件與 DOM 變更，ProseMirror 會把它讀回自己的 model，最接近真實打字。`execCommand` 雖然已標示 deprecated，Chrome 仍完整支援，而且是目前唯一能產生「可信」編輯的方法。用真正的 ProseMirror 實測過：多行、空行、中文、60 行長文都能正確轉成段落
2. **逐行 `insertText` + `insertParagraph`**：如果方法 1 把換行合併了，就改用這個
3. **合成 `paste` 事件**（`ClipboardEvent` + `DataTransfer`）：ProseMirror 的貼上處理器能正確解析多行文字，但 claude.ai 會把長文字貼上自動轉成附件，所以只用在 2000 字以內
4. 全部失敗：確認列提供「複製文字」，讓你手動貼上（訊息仍保留在佇列，不會遺失）

### 佇列與排程（`src/background/service-worker.js`）
- 所有佇列異動都由 service worker 序列化處理（promise mutex），避免多分頁同時寫入造成覆蓋
- 每個項目：`id`（UUID）、`status`（`waiting` / `ready` / `sent` / `failed`）、`claim`（送出鎖定）
- **防重複送出**：送出前必須取得 claim（同一時間只會有一個分頁拿到），標記已送出要帶正確 token；已送出的 id 另外記錄，就算有過時的請求也無法再送一次
- `chrome.alarms` 排在最早的重置時間＋30 秒；service worker 每次被喚醒、瀏覽器啟動（`onStartup`）、安裝更新（`onInstalled`）時都會依佇列重建 alarm
- 只有被指派給該分頁的還原工作才會填入（點通知或「立即嘗試」），同時開多個 claude.ai 分頁不會每個都填

### 邊緣情況
| 情況 | 處理 |
|---|---|
| 分頁被關閉（等待中） | 不影響；重置時會開新分頁 |
| 送出過程中分頁被關閉 | 標記 `failed`（「請確認是否已送出」），**不會自動重送** |
| 瀏覽器重啟、alarm 遺失 | `onStartup` 與每次喚醒都會依佇列重建 |
| 多個 claude.ai 分頁 | 用量快照共用、輪詢由前景分頁負責；還原只指派給一個分頁；claim 防止重複送出 |
| 原對話已刪除／網址變了 | 確認列詢問「要在目前這個對話送出嗎？」 |
| 你已經手動送出相同內容 | (a) 用量未滿時你手動送出與佇列相同的文字 → 送出成功後自動從佇列移除；(b) 還原時若對話最後 3 則訊息有相同內容 → 詢問「標記為已送出 / 仍要還原 / 保留」 |
| 輸入框已有其他文字 | 詢問是否覆蓋 |
| 重置時沒開 claude.ai | 無法確認，仍會通知（標示「預計已重置」），開啟頁面時會再確認一次；如果還沒重置，就放回等待 |
| 重試 10 次仍未重置 | 發通知說明，項目留在佇列；下次開 claude.ai 輪詢到已恢復時會自動標為可送出 |
| 擴充功能更新後舊分頁 | 提示重新整理頁面 |

## 隱私

- 所有資料只存在 `chrome.storage.local`（佇列文字、用量快照、設定、log）；排隊訊息的附件存在擴充功能自己的 IndexedDB
- 附件只存在這台電腦上，訊息送出、刪除或「清除所有資料」時一起刪除；送出失敗的項目會保留附件，讓你之後再試
- 只有在你按送出、且判斷為「用量已滿」時，才會讀取輸入框內容
- 為了確認送出成功、偵測重複，會在本機比對對話中**最近幾則你自己的訊息**的文字；只做比對，不保存、不傳送
- debug log 只記錄事件、id、文字長度、附件數量與大小與狀態，**不記錄訊息內容與檔名**
- 唯一的網路請求是同源 GET 用量端點（以你的登入狀態），不連到任何第三方

## 已知限制

- 只支援 claude.ai 網頁聊天（含 Projects），不支援 Claude Code、桌面 App、行動版
- 附件只支援你從電腦加入的檔案（選檔、拖放、貼上圖片）；Google Drive／GitHub 等連接的附件、長文字貼上自動轉成的附件、重新整理前就加入的檔案不會排隊（照原本方式處理）
- 只有附件、沒有文字的訊息不會排隊。模型選擇與延伸思考等設定不會保存，還原時沿用頁面當下的設定
- 富文字格式（例如貼上的程式碼區塊）會以純文字還原
- 用量端點與 DOM 結構都不是公開 API，claude.ai 改版就可能失效（見下一節）
- 如果 claude.ai 在用量滿時把輸入框整個停用（不能打字），擴充功能也無法取得文字
- 自動送出需要 **Chrome 開著、電腦沒有睡眠、claude.ai 維持登入**。不符合時會在下次 Chrome 啟動／電腦喚醒後補做；擴充功能會開啟分頁並把視窗帶到前景（`execCommand` 需要輸入框有焦點）
- 自動送出的保護原則是「寧可不送，也不送錯對話、不重複送」：
  - 送出前一刻會再確認目前就是原對話；不是就改開原對話，原對話已刪除則停止並通知
  - 確定沒送出時（文字仍完整在輸入框）會重新整理分頁再試，最多 2 次
  - 可能已送出但無法確認時，標記失敗並發桌面通知，不會自動重試
  - 輸入框原有的草稿會先存進佇列（標記「草稿」，不會自動送出）再覆蓋
  - 在新對話頁排入的多則訊息，會依序送進第一則建立的同一個新對話
- 確認送出成功的方法是偵測使用者訊息氣泡；如果該選擇器失效，會改用「輸入框清空＋開始生成」的弱判斷並提示
- 重置時間是 claude.ai 回報的時間；以頁面文字推估時精度只到分鐘，解析失敗時是保守估計（5 小時）

## claude.ai 改版時最容易壞的地方

| 症狀 | 原因 | 要改的檔案 |
|---|---|---|
| popup 顯示「用量端點讀取失敗」、來源一直是「頁面提示」或「無」 | 用量端點路徑或回應欄位改了 | `src/content/usage.js`：`ENDPOINTS`、`FIELD_ALIASES`、`parseUsageResponse()` |
| 用量滿了卻沒攔截（端點也失敗時） | 上限提示的文字或位置改了 | `src/content/usage.js` 的 `LIMIT_PATTERNS`、`parseResetTimeFromText()`；`src/content/selectors.js` 的 `limitBanner` |
| 頁面跳出「找不到頁面元素『editor／sendButton／userMessage』，介面可能已改版」 | DOM 結構或 aria-label 改了 | `src/content/selectors.js`：在對應清單最前面加上新的選擇器 |
| 還原時顯示「無法自動填入輸入框」 | 編輯器換掉了（不再是 ProseMirror），或填入方式失效 | `src/content/editor.js` 的 `fill()` / `getText()` |
| 送出後被標記「失敗」，但其實有送出 | 使用者訊息氣泡的選擇器改了 | `src/content/selectors.js` 的 `userMessage` |
| 有附件時沒有排隊、提示「無法保存的附件」 | 附件卡片的選擇器改了，數量對不上 | `src/content/selectors.js` 的 `attachmentItem`（每個附件一張卡片） |
| 附件訊息排隊了，但輸入區的附件沒被移除 | 附件移除按鈕的選擇器改了 | `src/content/selectors.js` 的 `attachmentRemove` |
| 還原時「附件沒辦法自動加回輸入區」 | 上傳用的 `<input type="file">` 改了，或不再接受程式設定的檔案 | `src/content/selectors.js` 的 `fileInput`；`src/content/attachments.js` 的 `attach()` |
| 附件加回去了卻一直等不到送出（上傳逾時） | 上傳中指示的選擇器抓到別的元素 | `src/content/selectors.js` 的 `attachmentUploading` |

回報問題時，請在設定頁開啟 debug log、重現問題，再按「複製 log」附上（log 不含訊息內容）。

### 新增語系
複製 `_locales/zh_TW/messages.json` 到 `_locales/<語系代碼>/messages.json`（例如 `ja`），翻譯 `message` 的值即可。`{name}` 是具名佔位符，請保留。缺少的 key 會自動退回 `zh_TW`。

## 常見問題

**Q：這會讓我多用額度或繞過限制嗎？**
不會。它只是在你被擋的時候把訊息存起來，等額度恢復後再透過頁面上的送出按鈕送出，跟你自己晚點回來貼上送出完全一樣。它不會呼叫 claude.ai 的聊天 API，也不會重放任何請求。

**Q：我的訊息會被傳到哪裡？**
哪裡都不會。佇列只存在你自己 Chrome 的 `chrome.storage.local`（附件在擴充功能的 IndexedDB），重置後是透過 claude.ai 頁面本身的上傳按鈕送出，跟你自己操作一樣。擴充功能唯一的網路請求，是以你的登入狀態對 claude.ai 讀取用量資訊（GET）。

**Q：可以傳檔案或圖片嗎？**
可以。用量沒滿時完全正常，擴充功能不會干涉。用量已滿時，你從電腦加入的檔案（選檔、拖放、貼上圖片）會連同文字一起排隊，重置後自動加回輸入區、等上傳完成再送出（自動送出模式也一樣；有任何一個加不回去就不送，改發通知）。Google Drive 等連接的附件、長文字貼上轉成的附件無法保存，這種訊息會照原本方式處理並提示你。附件處理依賴 DOM 選擇器，建議裝好後先照 [TESTING.md](TESTING.md) 第 3b 節測一次。

**Q：電腦睡眠或 Chrome 關閉時會怎樣？**
Chrome 關閉時無法通知。下次開啟 Chrome 時，擴充功能會依佇列重建排程；如果重置時間已經過了，會立刻檢查並通知你。電腦睡眠中錯過的 alarm，醒來後也會補觸發。

**Q：重置時沒開著 claude.ai，怎麼確認真的重置了？**
沒辦法確認，所以通知會寫「預計已重置（尚未確認）」。你點通知開啟對話後，頁面會再查一次用量；如果還沒重置，訊息會放回等待，不會硬送。

**Q：自動送出安全嗎？**
自動送出預設關閉。開啟後，訊息可能在你不在電腦前時送出，而那時對話情境可能已經改變。就算開啟了，送出前仍有 3 秒倒數可以取消。建議只在確定需要時使用。

**Q：同一個對話排了好幾則訊息會怎樣？**
會依排隊順序一則一則處理：送出第一則後，等 Claude 回應完成，再還原下一則並顯示確認列。

**Q：popup 一直顯示「用量端點讀取失敗」？**
claude.ai 可能改了內部端點。擴充功能會改用頁面提示文字判斷，大部分情況仍能運作，但重置時間可能是估計值。請到 Discord 或 GitHub Issues 回報，並附上 debug log。

**Q：支援 Edge、Brave、Arc 嗎？**
這些 Chromium 系瀏覽器理論上都能用「載入未封裝項目」安裝，但目前只在 Chrome 上開發。歡迎回報使用結果。

**Q：支援 Claude 桌面 App 或 Claude Code 嗎？**
不支援，只支援 claude.ai 網頁版（含 Projects）。

## 參與貢獻

歡迎各種形式的貢獻：

- **回報問題**：開 GitHub Issue，說明 Chrome 版本、重現步驟，並附上設定頁「複製 log」的內容（log 不含訊息內容）
- **claude.ai 改版修正**：最常見的貢獻。請參考上面的[改版對照表](#claudeai-改版時最容易壞的地方)，通常只需要修改 `selectors.js` 或 `usage.js`
- **翻譯**：新增 `_locales/<語系>/messages.json`
- **功能建議**：先到 Discord 或 Issues 討論，再開 PR

開 PR 前請：
1. 保持零依賴、不需建置（不引入框架或打包工具）
2. 不新增權限，不加入任何外部網路請求或遠端程式碼
3. 不加入任何呼叫或重放 claude.ai 聊天 API 的行為
4. 介面文字放在 `_locales`，不要寫死在程式碼裡
5. 依照 [TESTING.md](TESTING.md) 跑過相關的測試項目
